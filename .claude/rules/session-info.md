## ID разговора: `/status` и меню правой кнопки

Пришло отзывом (0.13.41, IntelliJ IDEA на маке): «хочу, чтобы агент передал что-то в другую сессию, для этого
нужен её id - дайте его прочитать или скопировать». Панель id разговора не показывала нигде.

**Адреса для других сессий в карточке нет, и это решение, а не недоделка.** CLI записывает каждый запущенный
процесс в `sessions/<pid>.json` своей папки конфигурации: id разговора и имя, по которому ему пишут другие
сессии (`amazing-claude-code-81` - папка проекта и хвост), и у агента есть инструменты «список сессий» и
«отправить сообщение» с этим именем как адресом (проверено 2026-10-17 на 2.1.293 из вкладки панели). Первая
версия карточки показывала это имя, прочитанное из реестра по id разговора. Живьём не сработало: имя, вставленное
в соседнюю вкладку, агент принял за непонятный идентификатор и пошёл искать его по репозиторию - про свои
инструменты переписки он сам не вспоминает. Макс: «убери вообще». Остались id и команда для терминала.

- **`/status` - команда панели** (`panelCommands` в `catalog.ts`, `runLocal` в `App.tsx`). Свою CLI в потоке
  отклоняет. Панель шлёт `sessionInfo`, окно отвечает (`ClaudePanel.sendSessionInfo`), в ленте встаёт строка
  `SessionInfoRow`: id и команда `claude --resume <id>`. Заголовок сверху и поля столбиком: подпись с
  пояснением, под ней значение плашкой, которая копируется целиком по клику (`CopyButton` с `children`). Первая версия была таблицей с колонкой под одно слово «SESSION» и копированием квадратиком сбоку -
  Макс: «смотрится стрёмно, под тайтл не надо целый столбец». Столбиком карточка одинакова на любой ширине.
  Строка локальная: в журнал не пишется, телефон её не видит, после перезагрузки панели её нет - это ответ на
  вопрос в моменте, как вывод `/status` в терминале.
- **Id берётся у IDE** (`conversationIdOf`), а без него - из состояния вкладки (`case 'sessionInfo'`): сброс
  состояния панели свою отметку теряет, IDE - нет.
- **Меню правой кнопки собирает браузер, а не страница** (`PanelContextMenu`, ставится в `WebviewHost`). Раньше
  там стояли браузерные Back, Forward, Print, View Page Source. Убираются они поимённо (`BROWSER_ONLY`), а не
  оставляется разрешённое: правка над полем, Copy над выделением, подсказки орфографии и всё, что браузер
  добавит завтра, остаются, пока кто-нибудь не решит иначе. Разделители, оставшиеся с краю или подряд,
  снимаются (`dropped`, с тестом). Пустое меню CEF не показывает вовсе.
- **Пункт «Copy Session ID» знает вкладку заранее.** Меню строится на потоке браузера, и спросить страницу в этот
  момент нельзя: ответ не успеет. Поэтому страница сама сообщает окну открытый разговор и слова для пункта при
  каждой смене вкладки или её разговора (сообщение `sessionMenu`, `WebviewHost.sessionMenu`). Слова едут со
  страницы, потому что словаря панели у IDE нет. У вкладки без разговора (новая, статистика, сценарии) пункта
  нет.
- **Эффект, который шлёт `sessionMenu`, стоит выше раннего выхода `App`** (экран входа). Поставленный ниже, он
  менял порядок хуков между отрисовками, и харнесс падал белым экраном.
- **Режим браузера в отдельном процессе тоже это умеет.** В WebStorm 2026.2 браузер панели живёт в `cef_server`
  (удалённый JCEF), и меню там идёт через `RemoteMenuModel` - список, на котором работают все вызовы,
  которыми пользуется `PanelContextMenu` (проверено по классам платформы).
- `sessionMenu` и `sessionInfo` телефону запрещены (`RemoteCommands.DENIED`): меню есть только у окна IDE, а
  строка - ответ своей ленте. Счёт: фича `session_info` и на `/status`, и на копирование из меню
  (`onSessionIdCopied`, пункт меню строит окно, сообщения нет).
- Проверить без IDE: харнесс, любой сценарий с полем - набрать `/status` и Enter, плеер отвечает выдуманным
  id, клик по плашке меняет значок на галочку. Меню правой кнопки
  в харнессе не видно, это меню браузера IDE: живьём - песочница, правый клик по ленте (пусто без выделения,
  кроме «Copy Session ID»), по выделению (Copy и пункт), по полю ввода (правка, орфография и пункт).
